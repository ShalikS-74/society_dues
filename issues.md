# Static Code Analysis Issues

The following issues were identified from the initial Pylint, Flake8, and Bandit reports. Security issues are listed first because they can affect the safety of the society dues data.

| Issue | Type | Line(s) | Description | Fix Approach |
|-------|------|---------|-------------|--------------|
| SQL injection risk in dues insertion | Security - Medium (Bandit B608) | 9 | The SQL `INSERT` query is created using an f-string. If a flat number or month contains malicious SQL, it could change the database query. | Use a parameterized query with `?` placeholders and pass the values separately to `execute()`. |
| Unsafe use of `eval()` for late-fee calculation | Security - Medium (Bandit B307) | 21 | `eval()` can execute arbitrary Python code. A malicious rule could access or modify data instead of only calculating a late fee. | Replace `eval()` with a restricted arithmetic-expression parser that allows only numbers and basic operators. |
| Hard-coded treasurer password | Security - Low (Bandit B105) | 5 | The password is written directly in the source code. Anyone who can view the file can read it, and changing it requires editing the program. | Remove the unused password. If authentication is required later, store credentials securely outside the source code. |
| Mutable default argument in `addDue()` | Reliability - Warning (Pylint W0102) | 8 | The default `history=[]` list is created once and shared between function calls. This can cause records from older calls to appear in later calls unexpectedly. | Use `None` as the default value and create a new list inside the function when needed. |
| Inconsistent return value in `collect()` | Reliability - Warning (Pylint R1710) | 12-16 | The function returns the amount when a payment is found, but returns nothing when no matching due exists. This makes the function result inconsistent. | Return a clear value such as `None` when no matching record is found, and document the behaviour. |
| Incorrect comparison with `None` in `pending()` | Style/Reliability - Warning (Flake8 E711, Pylint C0121) | 29 | The code uses `rows != None`, which is not the recommended Python comparison and is unnecessary because `fetchall()` returns an empty list when no rows are found. | Return the list comprehension directly, or use `is not None` only where a `None` check is truly required. |
| Non-standard function name and missing documentation | Code quality - Convention (Pylint C0103, C0114, C0116) | 1, 8, 12, 19, 27, 34 | The module and functions do not have docstrings, and `addDue` does not follow Python snake_case naming convention. This makes the code harder to understand and maintain. | Add short docstrings and rename `addDue` to `add_due`, then update its callers. |
| Long lines and missing blank lines | Style - Convention (Flake8 E501, E302) | 4, 12-15 | Some statements are longer than the configured line limit and functions are not separated by the expected blank lines. | Wrap long statements across lines and use two blank lines between top-level functions. |
